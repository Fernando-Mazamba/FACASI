Atualização

Instalar uma versão nova sem Terminal e sem perder dados

← Documentação

Como funciona

Cada versão traz os ficheiros do sistema e, quando necessário, migrações da base de dados (pasta sgi/migrations/<versão>/). Os seus dados nunca vêm no pacote: config.php e a pasta de dados não são tocados ao extrair.

Enquanto houver migrações por aplicar, o SGI fica em modo de manutenção: a API responde «O sistema está a ser atualizado» e só o assistente de atualização funciona. Assim não se gravam dados num esquema incompleto.

Passo a passo

  1. Cópia de segurança prévia (recomendado). Plataforma → Cópias de segurança → «Criar cópia de segurança agora» → «Descarregar». O assistente faz outra cópia automaticamente, mas ter uma no seu computador é a garantia final.
  2. Enviar as partes. cPanel → Gestor de ficheiros → pasta que contém sgi/ → Carregar as partes ZIP da nova versão.
  3. Extrair por cima. Extraia cada parte na mesma pasta e aceite substituir ficheiros. config.php e os dados mantêm-se.
  4. Abrir o assistente. https://SEU-DOMINIO/sgi/atualizar/ → entrar com a conta de administrador da plataforma (outras contas são recusadas).
  5. Verificar. O ecrã mostra a versão dos ficheiros, a versão do esquema da base de dados, os requisitos (incluindo «Pacote completo») e a lista de migrações pendentes.
  6. Atualizar agora. O assistente: (1) cria uma cópia completa (base de dados + ficheiros) com manifesto de contagens e SHA-256; (2) aplica as migrações; (3) gera chaves VAPID se faltarem; (4) compara o estado depois com o manifesto de antes.
  7. Ler o relatório. «Atualização concluída sem perda de dados» significa: mesmas contagens de linhas e mesmos hashes (sobre as colunas que existiam antes) em todas as tabelas de dados, todos os ficheiros com o mesmo SHA-256 e todas as versões finais com SHA-256 confirmado. Pode descarregar o relatório (JSON).
  8. Telemóveis. A aplicação instalada atualiza-se sozinha na próxima abertura com ligação (o service worker de cada versão tem um identificador novo).

Se algo correr mal

  • O relatório mostra «Atualização com problemas» e a lista de diferenças. Nada é apagado.
  • No mesmo ecrã, em «Restaurar uma cópia», escolha a cópia …antes-atualizacao…, escreva RESTAURAR e confirme. Antes de restaurar é feita mais uma cópia do estado atual.
  • As migrações são idempotentes (podem ser repetidas): corrigido o problema, carregue novamente em «Atualizar agora».

Atualização 1.0.0 → 1.1.0 (testada)

A versão 1.1.0 acrescenta: dispositivos e tokens da aplicação, chaves de idempotência, subscrições push, equipamentos/QR, calendário no servidor, indicadores, importações e colunas de campo nos registos (UUID do cliente, GPS, equipamento). O teste T23 instala uma base com o esquema 1.0.0 e dados de teste (24 registos, 12 finais com ficheiro e SHA-256, anexos, NC, ações, catálogos) e executa este assistente no navegador: todas as contagens e hashes ficam iguais e os 12 finais mantêm o SHA-256. Ver Relatório de testes.

Não existia uma instalação 1.0.0 real da FACASI. O núcleo foi escrito nesta etapa como esquema 1.0.0 e as funcionalidades móveis como 1.1.0, precisamente para que o assistente de atualização fosse exercitado de forma real.
