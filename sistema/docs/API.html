1. Autenticação

Navegador: sessão + CSRF

POST /api.php/auth/login        {"email","password"}  → {user, org, csrf, …}  (cookie SGISESS: HttpOnly, SameSite=Lax, Secure em HTTPS)
POST|PUT|DELETE …               cabeçalho X-CSRF-Token: <csrf>   (sem ele: 403 {"code":"csrf"})
POST /api.php/auth/logout

Aplicação: tokens de curta duração + renovação

POST /api.php/auth/token     {"email","password","device_name"}
  → {"access_token","refresh_token","token_type":"Bearer","expires_in":900,"device_id"}
GET  /api.php/…              Authorization: Bearer <access_token>      (não precisa de CSRF)
POST /api.php/auth/refresh   {"refresh_token"} → novo par (o token de renovação roda a cada uso)
POST /api.php/auth/token/revoke                → encerra este dispositivo
GET  /api.php/auth/devices[?user_id=]          → dispositivos (o admin vê os de outros utilizadores da organização)
DELETE /api.php/auth/devices/{id}              → revoga imediatamente todos os tokens desse dispositivo
  • Acesso: 15 minutos. Renovação: 30 dias, rotativa. Guardados na BD apenas como SHA-256.
  • Reutilizar um token de renovação já substituído revoga o dispositivo inteiro (deteção de roubo).
  • Cada pedido consulta a BD: revogação, desativação do utilizador, suspensão da organização e mudança de palavra-passe têm efeito imediato.
  • Bloqueios: 5 falhas → conta bloqueada 15 min (423); 30 falhas em contas da mesma organização → organização bloqueada 15 min (429); 50 falhas do mesmo IP → IP bloqueado 15 min (429). Iguais para sessão e tokens.
  • Se o servidor remover o cabeçalho Authorization (alguns CGI), o .htaccess repõe-no; em alternativa aceita-se X-SGI-Token.

3. Sincronização sem duplicar e sem sobrescrever

  • Idempotency-Key (8–100 caracteres) em POST/PUT/DELETE: a mesma chave devolve a mesma resposta guardada (cabeçalho Idempotent-Replay: true) sem repetir a operação. Chave reutilizada noutra rota → 422.
  • client_uuid em POST /records: identifica o rascunho criado no telemóvel; um segundo envio devolve o registo existente com "duplicado": true.
  • lock_version em PUT /records/{id} e POST /records/{id}/finalize: tem de ser igual à do servidor; se não for → 409 conflito com a versão do servidor, para o ecrã de resolução.

  -d '{"email":"operario@exemplo.ao","password":"…","device_name":"Telemóvel do armazém"}'
